# ForgeSWE Coding Harness

<div dir="rtl">

## محیط هوشمند و امن برای مهندسی نرم‌افزار در ویندوز

**ForgeSWE Coding Harness** یک محیط دسکتاپ مبتنی بر هوش مصنوعی برای تحلیل، برنامه‌ریزی، ویرایش و تست پروژه‌های نرم‌افزاری است.

این پروژه فقط یک چت‌بات برای تولید کد نیست. ForgeSWE مانند یک دستیار مهندسی نرم‌افزار عمل می‌کند: ساختار پروژه را می‌خواند، وظیفه را به مراحل مشخص تقسیم می‌کند، تغییرات را به‌صورت کنترل‌شده پیشنهاد می‌دهد، دستورات واقعی را اجرا می‌کند، خروجی تست‌ها را تحلیل می‌کند و در صورت شکست، چرخه اصلاح خودکار را فعال می‌کند.

> هدف پروژه، ترکیب قدرت مدل‌های زبانی با کنترل، قابلیت ردیابی و ایمنی موردنیاز در کار واقعی روی کد است.

---

## چرا ForgeSWE؟

کار با ابزارهای هوش مصنوعی کدنویسی معمولاً بین دو حالت گرفتار می‌شود:

- ابزارهایی که فقط متن و کد پیشنهادی تولید می‌کنند و به پروژه واقعی دسترسی ندارند؛
- ابزارهایی که بدون شفافیت کافی، مستقیماً فایل‌ها و دستورات سیستم را تغییر می‌دهند.

ForgeSWE بین این دو رویکرد قرار می‌گیرد:

- مدل هوش مصنوعی برای تحلیل و پیشنهاد استفاده می‌شود؛
- بک‌اند محلی، مسیرها، فایل‌ها و دستورات را اعتبارسنجی می‌کند؛
- تغییرات به‌شکل Diff و Search/Replace قابل بررسی هستند؛
- عملیات حساس نیازمند تأیید انسانی‌اند؛
- هر مرحله، خروجی و وضعیت مشخص دارد؛
- در صورت شکست، علت خطا و تلاش‌های اصلاحی قابل مشاهده است.

## قابلیت‌های اصلی

### برنامه‌ریزی هوشمند وظایف

یک درخواست ساده را به یک پلن اجرایی چندمرحله‌ای تبدیل می‌کند. هر مرحله نوع، ریسک، فایل هدف، دستور اجرا و وضعیت مستقل خود را دارد.

### نقشه‌برداری از ساختار پروژه

با RepoMap، توابع، کلاس‌ها، importها، زبان فایل‌ها و تعداد خطوط پروژه استخراج می‌شود تا مدل پیش از تغییر، درک بهتری از ساختار کد داشته باشد.

### ویرایش کنترل‌شده کد

تغییرات با الگوی دقیق `SEARCH/REPLACE` اعمال می‌شوند؛ بنابراین به‌جای بازنویسی بی‌دلیل فایل، فقط بخش هدف تغییر می‌کند. پیش از ذخیره نهایی، گارد سینتکس نیز اجرا می‌شود.

### اجرای واقعی روی Workspace

ForgeSWE با فایل‌های واقعی یک پوشه محلی کار می‌کند و قابلیت‌های زیر را ارائه می‌دهد:

- باز کردن workspace موجود؛
- وارد کردن فایل‌ها؛
- ایجاد، ویرایش و حذف فایل؛
- اجرای تست و دستورات پروژه؛
- مشاهده خروجی ترمینال؛
- مشاهده Diff تغییرات؛
- بازگشت به snapshot اولیه.

### تأیید انسانی در نقاط حساس

دستورات بر اساس ریسک در سه گروه قرار می‌گیرند:

- `safe` — قابل اجرا بدون توقف؛
- `approval` — نیازمند تأیید انسانی؛
- `blocked` — غیرمجاز و مسدودشده.

توکن تأیید یک‌بارمصرف است و به hash همان دستور متصل می‌شود؛ بنابراین تأیید یک دستور، امکان اجرای دستور دیگری را ایجاد نمی‌کند.

### اصلاح خودکار خطا

وقتی تست یا یک دستور با خطا تمام می‌شود، ForgeSWE می‌تواند:

1. خروجی خطا را تحلیل کند؛
2. علت احتمالی را توضیح دهد؛
3. پچ دقیق پیشنهاد کند؛
4. پچ را روی workspace اعمال کند؛
5. دستور شکست‌خورده را دوباره اجرا کند؛
6. نتیجه را در تاریخچه Self-Correction ثبت کند.

چرخه اصلاح در رابط کاربری حداکثر سه تلاش دارد تا از حلقه‌های بی‌پایان جلوگیری شود.

### مدیریت مهارت‌ها

مهارت‌ها ماژول‌های قابل فعال‌سازی هستند و هرکدام نام، نسخه، دسته، پارامتر، مانیفست YAML و سیاست تأیید خود را دارند.

مهارت‌های پیش‌فرض پروژه:

| مهارت | کاربرد |
|---|---|
| `repomap_ast_indexer` | استخراج ساختار و نمادهای پروژه |
| `agentless_fault_localizer` | مکان‌یابی سلسله‌مراتبی فایل و خطا |
| `surgical_search_replace` | اعمال پچ دقیق با گارد سینتکس |
| `swe_test_verifier` | اجرای تست و تحلیل Exit Code |
| `security_static_scanner` | بررسی الگوهای ناامن و نشت کلید |

## نصب و اجرای پروژه

ابتدا وابستگی‌ها را نصب کنید:

```bash
npm install --legacy-peer-deps
```

### اجرای حالت توسعه

```bash
npm run dev
```

سرور روی پورت `3000` اجرا می‌شود. اگر این پورت اشغال باشد، برنامه به‌صورت خودکار یک پورت آزاد انتخاب می‌کند.

### اجرای رابط دسکتاپ

ابتدا بک‌اند را در یک ترمینال اجرا کنید و سپس در ترمینال دوم بزنید:

```bash
npm run electron:dev
```

### اجرای نسخه Production

```bash
npm run build
NODE_ENV=production npm start
```

در حالت Production، فایل‌های ساخته‌شده در `dist/` سرو می‌شوند.

## تنظیم مدل هوش مصنوعی

از بخش تنظیمات مدل در برنامه می‌توانید provider و مدل را تغییر دهید.

### Gemini

```env
GEMINI_API_KEY=your_api_key_here
```

### OpenAI-compatible

برای استفاده از providerهای سازگار با OpenAI، این موارد را در تنظیمات وارد کنید:

- نام مدل؛
- Base URL؛
- API Key؛
- مقدار Temperature.

کلید API در فایل پروژه ذخیره نمی‌شود. بک‌اند آن را در حافظه نگه می‌دارد و در پاسخ‌های کلاینت فقط نسخه ماسک‌شده کلید را نمایش می‌دهد.

## متغیرهای محیطی

| متغیر | مقدار پیش‌فرض | توضیح |
|---|---:|---|
| `GEMINI_API_KEY` | خالی | کلید اتصال به Gemini |
| `PORT` | `3000` | پورت ترجیحی سرور |
| `FORGESWE_DATA_DIR` | `.forgeswe-data` | محل ذخیره داده‌های محلی برنامه |
| `FORGESWE_DIST_DIR` | `dist` | محل فایل‌های Production فرانت‌اند |

فایل `.env.example` فقط یک قالب نمونه است و نباید با کلید واقعی جایگزین یا منتشر شود.

## امنیت و حریم خصوصی

ForgeSWE برای اجرای محلی و تک‌کاربره طراحی شده است.

اقدامات امنیتی فعلی شامل موارد زیر است:

- سرور فقط روی `127.0.0.1` گوش می‌دهد؛
- مسیرهای مطلق و مسیرهای خارج از workspace رد می‌شوند؛
- حملات path traversal با بررسی مسیر حل‌شده محدود می‌شوند؛
- دستورات مخرب یا پرخطر مسدود می‌شوند؛
- دستورات حساس به تأیید صریح نیاز دارند؛
- کلید API به‌صورت کامل به فرانت‌اند برگردانده نمی‌شود؛
- snapshot و rollback برای بازگردانی تغییرات وجود دارد؛
- `node_modules`، `dist`، فایل‌های محیطی و state محلی نباید در Git commit شوند.

دستورات زیر، یا نمونه‌های مشابه آن‌ها، مسدود یا محدود می‌شوند:

- حذف بازگشتی فایل‌ها؛
- خاموش یا ریستارت کردن سیستم؛
- `git reset --hard`؛
- `git push --force`؛
- اجرای PowerShell encoded؛
- دانلود و pipe مستقیم به Shell؛
- نصب پکیج و برخی interpreterها بدون تأیید.

> این پروژه برای استفاده محلی ساخته شده است و نباید بدون افزودن احراز هویت، کنترل دسترسی و سخت‌سازی شبکه روی سرور عمومی Deploy شود.

```text

├── server.ts                    # بک‌اند Express و منطق اصلی Harness

├── package.json                 # اسکریپت‌ها و وابستگی‌ها

├── electron-builder.yml         # تنظیمات ساخت نسخه ویندوز

│   ├── main.tsx                 # نقطه ورود React
│   ├── App.tsx                  # رابط اصلی برنامه
│   ├── index.css                # استایل‌های اصلی
│   ├── components/              # Diff، تنظیمات مدل و مدیریت Skills
│   ├── data/presets.ts          # مهارت‌های پیش‌فرض

│   ├── main.cjs                 # Electron main process
```

## محدودیت‌های فعلی

- پشتیبانی رسمی پروژه روی ویندوز متمرکز است.
- برنامه برای استفاده تک‌کاربره و محلی طراحی شده و احراز هویت شبکه‌ای ندارد.
- گارد سینتکس فعلی برای فایل‌های JavaScript/Node با `node --check` انجام می‌شود.
- Self-Correction تضمین نمی‌کند که همه خطاها را حل کند.
- ارسال محتوای کامل فایل‌ها به مدل می‌تواند در پروژه‌های بسیار بزرگ مصرف توکن را افزایش دهد.
- اجرای دستورات workspace دارای ریسک ذاتی است؛ قبل از تأیید، دستور و مسیر هدف را بررسی کنید.

## مشارکت در توسعه

برای مشارکت:

1. مخزن را Fork کنید؛
2. یک Branch جدا بسازید؛
3. تغییرات را همراه با تست اضافه کنید؛
4. `npm run lint` و `npm test` را اجرا کنید؛
5. یک Pull Request با توضیح دقیق تغییرات ارسال کنید.

لطفاً کلیدهای API، فایل‌های `.env`، پوشه `node_modules`، خروجی‌های Build و state محلی را Commit نکنید.
